# Original client: first playable path

Updated October 29, 2026, 1:44 PM US Central.

The real supplied Sparking iPhone client is the production foundation. Its
compiled engine, original screens, combat and animation systems are retained.
The browser and authored battle harness are internal tools, never replacements
or evidence of native gameplay. Android and ordinary iPhone remain paused.

## Development completed in the retained second source cohort

- Core schema 12 keeps exact accepted full Creator packets in the same
  transaction as their definition and ownership. Native reads check actual
  current ownership, save scope, active version and byte hashes. Historical
  descriptors with missing bytes require recovery rather than fabricated data.
- The native reader, full-form compiler and derived-master store have a
  separate strict full-packet path. Resource-free form rows and native root
  rows are retained together. Resourceful publication, original-engine
  attachment and gameplay admission remain closed.
- A native accepted-resource reader binds readonly file descriptors to exact
  captured hashes and ownership. An asynchronous movie candidate planner
  preserves immutable media bytes; it does not claim decoding/publication.
- Original iPhone resources can be preflighted from a pinned readonly catalog
  descriptor before bounded no-overwrite publication into the real assets root.
- Save export now shares the existing 256 MiB import budget and preserves the
  canonical save and an existing backup on refusal. Larger live saves are not
  given a falsely supported backup; streaming restoration remains unfinished.
- Tutorial update analysis recovered the actual PUT dispatch and relative
  tutorial suffix. Auth parsing/callback research remains incomplete. A
  previous 116-byte-helper scope description was corrected: the current
  wrapper tails a 704-byte function, not the unrelated 1,404-byte candidate.

These are source milestones. None establishes native launch or real combat.
Existing focused synthetic SQL/JavaScript evidence is retained without reruns.
C/Objective-C changes have not been compiled or executed in this cohort.

For progress reports, the startup diagnostic source checklist is four steps:
pinned binary inputs, reviewed entry source, compatible startup asset staging,
and actual native launch. The first two are done (2/4); the last two remain.
The login source checklist is parsed-root proof, candidate encoders, complete
sign-in contract, and native handler integration. Its first two are done
(2/4). These equal-count source checklists are not weighted readiness estimates
or a percentage of the whole game. Original-client battle/save and Creator-in-
battle runtime acceptance have not been reached.

## Present limits and continuation

The private original IPA is 1,144,358,271 bytes; the connected Drive fetch action
rejects files over 268,435,456 bytes before issuing a download reference. Its
old temporary transfer parts were removed after an earlier reconstruction.
The engine and genuine shells are restored. After both retained caches were
checked, Tin ran the reviewed selective Colab extractor. Its 778,241-byte
output was fetched from Drive and both exact original files were hash-verified
and restored readonly: the 649,088-byte AdjustSigSdk binary and 535,552-byte
opaque database seed. Neither the full IPA nor personal signing/save/key data
was transferred. Framework metadata and a complete compatible startup asset
set are separate pending inputs; the two recovered files do not prove launch.

The new plain-JSON auth path now has source proof through the actual installed
HTTP completion and JsonCpp reader. Native and JS encoders produce candidate
bodies at the document root. The sign-in callback forwards that entire root
to a further consumer, so complete response requirements are still being
traced and the HTTP routes remain closed. Do not label the encoder a login.

Native candidate handlers now retain one in-memory local issue from nonce to
sign-in, reject expired or rolled-back time, and return the remaining positive
TTL without extending the issue's original deadline. They are not installed.
The existing Foundation transport already fits the actual current client and
auth constructors' empty query. The optional ping has its own response wrapper
and still needs its concrete startup configuration contract. Ordinary APIs
also have a separate signed-response branch, so auth root proof does not
automatically admit tutorial, resources or battle responses.

To avoid reconstructing minimum resource lists one file at a time, the reviewed
cloud recovery helper now selects the complete existing 1,067-candidate original
iPhone resource inventory plus exact framework metadata. It verifies the whole
IPA in temporary Google-cloud scratch, preserves original bundle/tutorial
paths, and writes one current set of parts below32MiB. The existing notebook
was updated and byte-readback verified; Tin's Run-all step is pending. No full
game copy through the Mac, app build or resource-staging completion is claimed.
