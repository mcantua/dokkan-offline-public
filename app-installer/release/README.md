# Final-release boundary

`verify-release.py` refuses a final release unless the exact IPA and corresponding-source archive have complete, matching evidence. It requires the existing/new tests, capability implementation, notices/source/relink fulfillment, real Apple sign-in/profile/signature/install/launch/refresh, and actual Duo outer/inner/touch/fold/state checks. Simulator and test-fixture reports cannot satisfy hardware requirements. An unsigned build cannot satisfy the profile/signature checks.

The verifier checks reported completeness and artifact binding; it does not turn manually invented evidence into physical proof. Produce evidence with the actual signing/device/display tests, preserve redacted observations, and never set a requirement true merely to pass the gate. No passwords, account IDs, signing keys or device identifiers belong in shared reports. Device-private records remain in the ignored protected local area.

A candidate may be useful for continued testing while this gate fails. Do not rename or describe it as the final release. Apple's account restrictions or an app's unavailable capabilities are real limitations that must be resolved or explicitly agreed with Tin; they cannot be silently stripped or marked passed.

The report must explicitly include schema_version (integer1), test_fixture=false, artifact_sha256, source_bundle_sha256, source_commit (40 lowercase hex characters) and source_tree_sha256 (64 lowercase hex characters). Every verification boolean is required as a JSON boolean; strings, omitted values and integer substitutes do not pass. Duplicate JSON keys are rejected. A physical Apple/Duo section must explicitly say simulator=false. These fields are reported outcomes, not a template that should be marked true in advance.

The primary app must carry signed (unsigned=false), clean-source metadata bound to the evidence's commit/fingerprint and the actual corresponding-source archive hash. An extension's profile/signature cannot satisfy the primary app check. The gate reads the actual source/relink archive with its verifier, checks exact delivered file/lock/graph content, and independently recomputes the production fingerprint from delivered source bytes (including configured trust anchors and recipient path dependencies). A matching source hash/commit declaration alone is insufficient. The current supported fingerprint recipe must be delivered unchanged with the archive; unsupported recipe changes fail closed until reviewed. No archive source is executed, no Cargo/network command is invoked, and no personal device/account action exists in the gate.

All inputs/output stay within the single repo folder. The output must not overwrite an input IPA, source archive or evidence report. Signed artifacts/profile-containing products remain in ignored protected local storage; this gate is not permission to upload those files to GitHub.

Advertised free and paid account support require separate `apple.free_account_verified` and `apple.paid_account_verified` outcomes. No paid account is purchased or requested by this tool; unavailable coverage stays unverified until Tin decides scope. The functional section also separately requires actual stable-ID update/no-duplicate behavior, Keychain restore, biometric authorization, pairing-backup recovery, self-refresh, the explicit Shortcuts due-refresh action, expiry alerts and background interruption. A generic capabilities assertion cannot replace those real checks. Source delivery itself must explicitly be non-fixture and clean-source metadata.
