# Engine implementation and review notes — October 28, 2026

## Implemented
- Mandatory compiled engine dependencies: local MIT isideload 0.5.0 and idevice 0.1.68, pinned version and Cargo.lock. No fs-storage, keyring-storage, OpenSSL or default idevice AWS crypto features. Registry idevice is patched to the same local source so isideload uses the pairing TLS fix too.
- Async worker runtime, exclusive operation execution, bounded safe event queue and C ABI. `ai_backend_ready` indicates compiled engine availability, not live verification. Events have monotonic `operationId` and operation names; terminal `signed` is distinct from actual-install `done`.
- Apple sign-in, callback 2FA, resend/trusted-device/SMS actions with validated offered number IDs; UI sees only last two digits. Multi-team selection uses exact fetched team IDs. User-supplied password is zeroizing memory and not persisted. Session email/SPD and signing/anisette material go through native Keychain storage only.
- Explicit anisette HTTPS endpoint https://ani.jkcoxson.com. Upstream auth requests are locally restricted to HTTPS Apple hosts, redirects disabled, invalid-certificate acceptance and verbose transport disabled. Compile-time tracing is disabled, raw third-party errors are discarded. See downloads/isideload/PATCHES.md.
- Session restore, sign-out and lock API. Cancel generation and CONTROL mutex prevent a cancelled task committing success or clearing a later operation. In-memory auth cleanup is guarded by auth generation so it cannot erase a newly established session.
- Pairing syntax validation and native primary storage under engine.pairing. Device TCP endpoint configured-address (LocalDevVPN), actual Lookup/Lockdown uses native pairing and patched device certificate pin/signature verification. Native bridge owns backup encryption and authentication UI.
- IPA validator runs before Application::new, which receives only the extracted app directory. Archive input is restricted to the app's private imports/sources directories. Staging has unique owned paths and RAII removal.
- Certificate retrieval uses MaxCertsBehavior::Error; no automatic certificate revocation. Actual developer session App-ID quota is checked before registration. Free-account slot count conservatively counts installed apps with unexpired development profiles across teams/installers; unknown/wildcard profile usage fails closed. Paid membership bypasses free weekly quota. Checks happen before new device/certificate/App-ID mutations where membership evidence is available.
- Lower-level profile/certificate signing, then separately installation staging, progress, Lookup confirmation and unique installer-owned AFC staging basenames with durable cleanup intents written/fsynced before upload. Successful cleanup clears an intent; cancellation/crash leaves it for retry on the next authorized connection. Only recorded prefix-validated names can be removed, never a generic app directory. No fabricated install success. Confirmed source metadata changes only after actual successful install; one hashed stable IPA filename per bundle avoids component-length/path issues. One separate, protected, exact-hash unconfirmed transaction retains the latest user-approved input across interruption.
- Self-source registration packages only the current own app bundle/public provisioning profile into the latest protected IPA, revalidates it, and records actual expiry. Unsigned preview without a profile reports selfRefreshReady false. Refresh orders other apps before self; iOS may close the app while replacing itself, so completion after self install cannot be guaranteed.

## Important limits — not release claims
- No Apple credentials were entered, no Apple account operation was run, no VPN/device/Keychain integration was runtime-tested, and no iPhone install was attempted. Protocol/API responses and entitlement compatibility remain unverified on a real account/device.
- Apple membership metadata is not guessed from an Individual/Company label. Explicit iOS-program membership or an existing profile's isFreeProvisioningProfile supplies evidence. Fresh teams without recognized membership metadata or existing profiles fail closed before creating identities. This response-schema behavior requires account validation.
- Stable per-team bundle mapping is now implemented in identity.rs: main `org.tin.sideload.t<team hash>.a<original hash>`, extensions below that main prefix. Records separately retain originalBundleId, signed bundleId, teamId and extension maps. Repeat original imports, recognized already-signed imports and refresh reuse the same identity; actual self identity is preserved. Installed direct/common original.TEAM legacy IDs are adopted only with selected-team App-ID ownership evidence, otherwise conflicts fail before identity creation. Arbitrary third-party remapping without original metadata cannot be guessed. Changing bundle IDs may affect app-specific hardcoded identifiers or backend policies; real server/device behavior remains unverified.
- The initial basic-only capability gate has been superseded by the profile-backed capability continuation below. Malformed or XML/DER-inconsistent entitlements still fail closed, and unsupported/ungranted capabilities are never silently stripped.
- Nested .app and symbolic-link framework layouts are intentionally rejected by the archive validator until recursive signing/profile support is implemented. This limits some legitimate app packages.
- Native Keychain authorization currently expires after five minutes; a long operation can require opening/unlocking again. BG scheduling and biometric access cannot guarantee perpetual unattended refresh. Expired installer recovery may still require a computer.
- Upstream and local implementation memory is not a guarantee of complete zeroization of every internal third-party allocation. Persistent secrets are confined to Keychain; no raw errors or credential strings are exposed to UI logs.

## Profile-backed capability continuation
- Blanket basic-only gate replaced by bounded requested-entitlements reading plus entitlement_policy.rs. Unknown legal typed grants can be preserved when the actual selected-team Apple profile authorizes every value. Required features are never stripped; unused profile privileges are not copied.
- Exact app-group ownership/reuse/registration and multi-group assignment implemented; default/private Keychain identity regenerated, shared groups preserved only with exact grants. Source hardcoded foreign groups are not silently remapped. Documented feature requests cover common legitimate capabilities; memory/debugging/VA requests configure fresh App IDs only, preserving existing service configurations. Full status and genuine external-service/auth limits are in CAPABILITY-MATRIX.md.
- Independent signed-output verification is mandatory before creating a staged installable object. Main and each extension use exact authenticated-server profile bytes plus selected team, device and signing certificate. Stored expiry is the minimum verified expiry across main and every extension; warning regression added to existing expiry test.
- Source IDs already owned by the selected team are preserved even before installation, avoiding unnecessary changes to legitimate existing domain/container/service configuration.
- No account operations, MacBook/personal network use or phone installation were performed. Offline verification is not live installation or service verification.

## Interrupted install and installed-only refresh fixes
- Before AFC upload, a single protected pending-install journal commits the exact SHA256-verified user-approved source, intended signed identity/team/record, and bounded owned candidate path. Files and directory entries are synced. This is an unconfirmed transaction, not a claim that installation finished. New confirmed expiry/source metadata is written only after install success and actual device lookup.
- A crash or cancellation after sending may leave installation outcome uncertain. An installed app with that intent blocks automatic refresh with an explicit request to re-import its latest IPA; the installer never silently rolls it back using an older retained source. Explicit re-import of the same app can replace the one pending candidate. A different app cannot overwrite unresolved intent. Legacy source .ipa.pending inputs are also retained and block refresh until confirmed by re-import.
- Installed-app queries now reconcile records only after a successful real lookup. Query failure preserves metadata and source inputs. Confirmed absent imported apps are removed from refresh records and their owned sources cleaned up, so manual/automatic refresh cannot reinstall apps the user removed. Refresh independently checks the selected app is still installed before profile mutations. The currently running installer is retained even if a filtered device listing omits itself.
- On launch, only known UUID import files, owned numeric staging directories, unreferenced journal scratch and valid metadata transactions are cleaned or recovered. Working source files, pending latest input and durable device cleanup intents are preserved. Current ownExpiry is republished after confirmed self-record updates; next launch reconstructs self-source from the actual running bundle.
- Two grouped offline lifecycle regressions were added for failed/present/absent device lookup reconciliation, exact pending-source retention/replacement, truthful confirmed expiry, self expiry, and conservative startup cleanup. They are delegated to the root's single combined final essential regression run to avoid redundant tests. No account or device calls were made.
