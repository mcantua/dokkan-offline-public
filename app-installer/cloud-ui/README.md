# Hosted native UIKit and Keychain checks

Manual GitHub Actions workflow: **App Installer cloud verification and candidates**. Root dispatches a necessary run after source review. The official `xcode-27` hosted image is selected, with explicit discovery of a genuine installed iOS27.1+ SDK and actual iPhone Duo simulator type/runtime. Older SDKs fail prerequisites. The Duo OS is tried first. Only a bare-OS startup failure before app installation may use one supported regular iPhone on the same27.1 runtime; its actual model/fallback and unverified Duo status are explicit in evidence. An app/test failure never triggers device substitution. Source/tool/output paths live under the checkout `AI-Workspace/claude-chatg`.

The job compiles the actual Rust library for the runner's simulator architecture and links every production Objective-C file. Simulator tests use standard Xcode ad-hoc signing without an Apple account or Team identity; built entitlements/signature summary are saved, not invented. Device candidates stay unsigned and simulator results cannot satisfy the physical-device release gate.

The two UIKit test cases check actual empty login/settings launch and responsive main layout. They also capture the actual simulator display report and explicitly labelled fixture checks for camera rails, invalid geometry,44-point controls/logical hit-testing, nonsecret unsent-field preservation, progress preservation and navigation preservation during forced view resizing. A test-only service supplies labelled metadata and a target-routing counter; it performs no account, signing or installation operation. Forced sizes/camera geometry are not hardware folding or native-panel evidence.

The same hosted XCTest target includes SecureStoreBootstrapTests: two real Keychain metadata guard tests with only test-owned dummy items and cleanup. RefreshLifecycleTests adds two expiry/cooldown and actual cancellation/reminder-policy cases without mocking authentication. No test fakes successful LocalAuthentication or supplies Apple credentials. Any simulator entitlement or API limitation must fail/report as unverified rather than be skipped as passed.

The job creates one new named simulator, boots only its returned UUID, and shuts down/deletes that UUID on exit. OS-managed CoreSimulator runtime/container data are unavoidable ephemeral hosted caches outside the checkout; this exception is disclosed in provenance. Project tools/Cargo/Rustup caches, DerivedData and evidence stay in the repo folder. No existing device is booted or deleted. No Tin Mac, personal network, physical phone, developer-download login or license bypass is used.

Optional `package_candidates=true` runs the genuine-device-SDK unsigned candidate packager, generated-project validator and minimal native-kit builder independently of simulator startup. An integrity-checked unsigned candidate artifact includes its matching source/relink archive, XCResult, logs and provenance; a separate small kit avoids downloading the whole source archive to the Mac. Both new uploads must exist before pruning the previous matching kit/source pair. Failed or standalone test runs use a separate diagnostics artifact and cannot delete the last complete distribution pair. Only artifacts from this exact workflow and its explicit App Installer name whitelist are pruned. Unit Creator is untouched.

Official sources and exact hardware steps: `ios/display-evidence.md`. Tool provenance/hashes: `downloads/cloud-ui-tools/SOURCE.md`. There is no documented pose-changing CLI in the researched Apple references; installed `simctl` help is captured for supported-control discovery, without inventing fold commands.

The combined final check runs the revised critical core regression suite and vendored idevice TLS/SNI checks using the macOS host SDK (not the simulator sysroot). Targeted Python failure-case checks already passed with the affected fixes; the cloud run checks actual generated candidate/source/kit outputs instead of repeating those unit checks. Repeat only failing or affected checks if a later change requires it. The UIKit cases also request actual owned-simulator panel-power transitions through display-driver.py, verify observed scene sizes/state, and save raw IO evidence. A test-only Documents nonce/phase bridge is compiled only in XCTest, not the product. The driver parses Integrated Connected Screens from actual enumeration and never hardcodes IDs or calls private hinge controls. Power-only changes that do not move the app scene fail the actual-transition check; geometry fixtures cannot substitute for it.
