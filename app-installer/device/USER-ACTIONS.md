# What Tin needs to do for the first real installation

Everything that can run without your Mac or phone is prepared in the cloud first. These steps have **not** been performed. The app is not called fully working until the real device checks pass.

1. **Approve the exact local setup step when asked.** It uses your MacBook, a USB cable, your iPhone and the internet connection you approve. The assistant will state the Rust transfer's exact size/hash first. Xcode may contact Apple to register this phone and create/reuse its development certificate/profile. The optional official pairing-tool download is 57,690,695 bytes. No Mac or personal connection use begins merely because it is connected.
2. **Use the small native setup kit after approval.** The assistant verifies its exact download size/hash and places it in the same `AI-Workspace/claude-chatg` folder. It contains only the needed native source/resources and cloud Rust library—not Unit Creator, a full Git clone or a Mac Rust installation. Double-click **Run-App-Installer-Setup.command** inside `app-installer/device/`. It shows the plan first; choose **Run approved setup** only after the exact local use has already been approved. Apple account/device choices remain local.
3. **Connect and unlock your iPhone.** Tap Trust on the phone if it asks. Enable Developer Mode in iPhone Settings if Xcode requests it; that can require a restart and another approval on the phone.
4. **Use an existing Xcode identity first.** The helper checks the installed full Xcode/SDK before phone/account discovery. If Apple sign-in or a certificate/account change is needed, it stops with that exact action: Tin’s current approval requires separate approval for Apple-credential changes. After that approval, use Xcode → Settings → Accounts locally and choose your intended free Personal Team or paid development team. Passwords and codes stay in Apple’s UI or on the phone, never chat. Private signing keys stay in OS Keychain.
5. **Let the assistant run the prepared compatibility/build/sign/install steps within your approval.** The tools check the real model, iOS version and installed Xcode SDK before installing. If Xcode is too old, installation stops; the tools never fake an SDK mark. The native bootstrap uses one stable app identity and the exact minimal Keychain entitlement. A full free-account app slot requires your decision about what to remove; nothing is deleted automatically.
6. **Finish pairing on the phone.** Use the verified official idevice_pair app over USB: select your phone, choose **Lockdown**, then **Load/Create**, and **Validate**. Do not choose Remote/RPPairing. Save one temporary file as `app-installer/device/private/pairing.mobiledevicepairing`, with that folder kept private. This export contains private material. Transfer it only by an approved direct local method, import it into App Installer, and delete the temporary export after secure import and pairing validation succeed. Do not upload it here or to GitHub. The app keeps its Keychain primary and one encrypted backup.
7. **Install/open LocalDevVPN from its verified App Store page when approved:** https://apps.apple.com/us/app/localdevvpn/id6755608044. Allow its VPN configuration on the phone. Keep its default interface `configured-address/32` and peer `configured-address/32` unless the assistant has verified a different setup. The installer connects to peer `configured-address`. VPN must stay on while signing/installing/refreshing.
8. **In App Installer, sign in and finish the device checks with the assistant.** Approve Face ID, enter Apple's code on the phone, choose the same development team, and import pairing. Check that the installed list and this app's real expiry appear. Install a small app you own or are allowed to use, then import its next version with the same bundle ID and confirm it updates the same app. Refresh the test app, then the installer; relaunch and confirm the saved account/pairing still work and expiry moved forward. No raw account/pairing logs are needed.
9. **Allow expiry alerts if wanted and add the Shortcuts guide.** The app's guide explains the daily open/unlock step. iOS can delay background work and Face ID cannot unlock unattended. Recovery after the installer actually expires can need a computer; the assistant will not promise otherwise.

The old Monday handoff is a review checkpoint, not a substitute for finishing these checks. First-install execution still waits for your explicit Mac/network/device approval and a usable authorized connection.

Separate verification is still needed for both free and paid account modes. If only one is available, the other stays unverified; this setup never asks you to buy an account. Recovery from the encrypted pairing backup, protected Keychain after relaunch/self-update, cancellation/background interruption, the actual daily refresh action and expiry alerts must also pass before a full-completion claim.
