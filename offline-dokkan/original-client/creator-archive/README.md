# Bound Creator creations archive

`ODCreatorContentArchive` implements the existing `userContentArchive` status/save/restore contract, with the same `Creations-for-reinstall.zip`, `dokkan-user-content` manifest v1/v2 and virtual gallery-document format used by `unit-creator/dock/src/com/personal/aihub/UserContentArchive.java`. The actual saved-version envelope comes from `web/src/ios-native.js`: JSON header, newline and original project JSON. Archive documents are issued/restored by the same native ODCreatorSession authority, not copied from its private state file.

Native construction supplies the owned tools-resource root, an optional user-granted external folder, a current-scope callback and Session snapshot/restore callbacks. A page supplies only action/gallery data. No Core/player database, master/source archive, account/settings directory, credentials, signing material or API/Sparking keys are part of the archive scope. The root's `assets` and `patches` collections use the existing Java resource-prefix/extension allowlist with private/hidden directories excluded; projects/versions arrive only as validated virtual document data. Gallery snapshots reject private fields and require their referenced resources. Missing external folder reports available=false. Private app storage is not advertised as surviving uninstall.

The native wrapper serializes each operation and streams ZIP data with bounded buffers. `zip_stream.c` reads/writes standard ZIP32 using system zlib, including the Java writer's deflated data-descriptor form. It rejects encrypted/ZIP64 archives, links/directories, duplicate names, overlapping or hidden local records, mismatched headers, CRC errors, excess files/bytes and truncated/extra streams. The wrapper additionally checks canonical relative paths, per-entry SHA-256/size against the complete manifest, structured document/gallery bounds and every existing resource conflict before activation.

Restore stages resources inside the bound private root, verifies all entries before activation, publishes only absent files through no-replace hard links, and invokes one atomic Session document merge. It never overwrites a differing document/resource. A failed native merge rolls back only this job's newly installed, still-identical resource files; changed files are preserved. Gallery documents return as a verified snapshot for the existing IndexedDB restore path, without leaving stale native gallery mirrors. A successful native document receipt is durable; later scope loss must not turn a committed merge into failure. The external archive stays unchanged for retry.

Save uses NSFileCoordinator, one exclusive temporary file, fsync and atomic replacement of the same archive, preserving a changed/invalid existing archive and avoiding dated/emergency copies. Cleanup deletes only staging objects this operation successfully created. Restore cleanup is descriptor-relative and does not follow links. The native caller must retain its folder security-scope grant, prevent conflicting workspace mutations, drain prior writes/downloads and revoke the context before releasing its native lease. The scoped tools wrapper supplies those gates; Session authority remains separate from the tools filesystem.

Limits match the Java format:10,000 content entries,512MiB per media entry,2GiB total content,8MiB manifest,1,000 gallery documents/16MiB total with8MiB each. Native document authority further limits its project/version snapshot to96MiB. ZIP paths support the Java500-character bound with up to1,500UTF-8 bytes. Large media are streamed; no complete archive is loaded into memory.

One affected iOS16.5-header Objective-C/C syntax batch passed. One portable native ZIP integration batch passed standard-reader roundtrip, Java-shaped deflated streaming descriptors, CRC corruption rejection and original/sentinel preservation. No unchanged app tests or packages were run. Actual Foundation restore transaction/rollback, user security-scoped Files-provider authorization and phone performance remain runtime acceptance work; the portable ZIP evidence alone does not prove those boundaries or whole-game completion.
