# Actual resource-response projection

`resources-projector.js` is data-only projection shared unchanged between bundled JavaScriptCore and Node. It does not implement game screens/mechanics or authorize a network route. Input is one native atomic canonical-player snapshot/admission, separately provisioned persistent offline identity, reviewed master/fresh-player policy sections and the schema-only observed resource response. It never reads the source account cache or adopts captured values.

Grounded fields currently map actual persisted Core ACT/rank/rank EXP/max ACT and stone/Zeni ledger balances. An absent balance is zero holdings, not a grant. User numeric ID/name must be supplied by persistent native offline provisioning; they are not an online account identity. With no owned cards, the actual owned collection projects as empty. Nonempty owned cards require native per-instance policy and pin actual instance/SA/EXP values; stock cards retain their real master ID, while modified/custom rows require the admitted native engine-card binding instead of assuming a template ID or inventing a numeric ID. Unknown EXP is unavailable rather than fabricated. Policy cannot override canonical balances or owned instance IDs.

`ios/ODResourceResponseProjector` loads the authored module and sanitized schema through hash-pinned, bounded read-only files, then evaluates only that authored module in its private serial JavaScriptCore context. Trusted native policy receives the actual atomic player envelope; policy data is copied as JSON and never evaluated as code. Main-owned context checks run before/after projection. The owner method `originalClientPlayerSnapshotForProfile:expectedSaveScopeSHA256:reply:` checks the exact persisted scope and reads the canonical snapshot/own identity in one existing-owner queue block, preventing same-owner import between those operations. Missing configuration/changed context returns fixed errors, never raw cache/URL/account data.

All remaining user/tutorial/capacity/card/team/inventory/event/mission/banner fields require actual native storage, verified master facts or explicit approved fresh-player policy. The module does not blanket-fill unknown collections with `[]`, manufacture unlocks or copy resource samples. Observed types do not prove requiredness or every possible variant: the conservative validator requires covered observed fields, rejects unreviewed/redacted names, unknown shapes and unobserved populated array items, and retains diagnostics. Incomplete projections have no serialized success body.

`research/cached-resource-response-schema.json` is sanitized schema evidence from the actual Android export. Scalar values were removed and unsupported field names redacted; iPhone runtime compatibility is unverified. The cache filename/path match is not a verified current HTTP method. Even a shape-compatible body does not admit a route: current route/method/transform and real iPhone use must be independently established before an authored local handler is installed. No login/home response route is installed by this module.

Initial own-player policy follows the approved start-empty/nothing-unlocked direction. Rank/ACT and any capacity/EXP facts must come from the actual selected master; tutorial stage enums and unimplemented capacities remain explicit policy requirements. The played source account's tutorial/progression/currency values are never defaults. Fresh stable numeric wire identity/name is technical native provisioning, not a reason to request an online account or copy its state.

One focused scenario ran the recorded module revision on the actual fresh Core11 snapshot and projection identity emitted by the native bootstrap scenario, with the observed sanitized schema. It verified real persisted identity/ACT/rank/EXP/ledger values and the actual empty collection, rejected a forged balance override and changed scope, and confirmed incomplete policy has no serialized response or admitted route. It reused the existing Core fixture rather than rebuilding/retesting unrelated Core features. Those fresh-player paths remain unchanged; their evidence is reused after the later custom engine-ID guard, whose real engine binding remains unverified. Exact tested/current hashes and scope are in `projection-evidence.json`. Affected Objective-C/JSC and typed C bridge source compiled with warnings treated as errors. Neither check is an original iPhone request, complete resource payload or gameplay proof.
