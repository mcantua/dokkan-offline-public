# Original-client Duo geometry bridge

This authored component consumes the actual renderer's current view/window/scene geometry. It never sizes from `UIScreen.mainScreen`, guesses the current display from a device name, reloads a game scene, modifies saves or stretches a game canvas. It reads current safe areas and active UIKit occlusion/division regions; a fold is recorded and rendered through. A transition update and one delayed settling update handle changing reserved regions.

`ODDuoDisplayBridge` is an explicit host API: retain one per renderer and call `refresh` from layout/safe-area changes, plus `refreshAfterTransition:` with the owning controller's real transition coordinator. Its callback supplies current raw geometry for an engine adapter. Missing APIs, malformed regions and read failures are explicit availability/completeness flags; fixed-canvas placement refuses an incomplete region read. Raw safe-area geometry remains available without claiming complete camera knowledge. `sceneGeometry.fillsScene` means only that the current window fills its scene; it is not evidence that an SDK26 source executable fills either physical Duo display.

The optional `ODDuoInstallOriginalRendererObservation` attachment is based on actual decoded metadata from the supplied 6.6.0 client: its own `CCEAGLView.layoutSubviews` encoding is `v16@0:8`. Runtime installation checks the class derives from UIView, owns this exact method and retains this ABI. It invokes the original layout first and then emits a snapshot. It does not assume Cocos C++ function addresses, call unverified framebuffer methods or resize the original renderer. Installation/removal is main-thread only; removal refuses to overwrite another component's later method replacement. This source is not injected or installed into the IPA by this change.

`ODDuoViewport.c` offers optional fixed-canvas placement and inverse touch mapping when a verified host supplies the engine's actual logical dimensions. It uses uniform scale inside safe, unoccluded content. Letterbox touches reject. The conservative bounded camera-placement algorithm preserves safe placement without promising a globally optimal packing. The original engine may instead consume raw geometry and implement its verified adaptive layout. Fixed-canvas placement is a helper, not the final Duo game layout or proof of fullscreen adaptation.
