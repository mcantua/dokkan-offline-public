# Original iPhone client local transport

`ODGameHTTPABI` performs read-only runtime preflight against the actual supplied arm64 6.6.0 main executable's `HttpAsynConnection` method encodings and response ivar layout. It never writes an ivar, swizzles a selector or calls the source patcher. Source identity must separately be pinned by the trusted loader. Static ABI evidence is in `research/ios-runtime-contracts.json`.

`ODLocalURLProtocol` supplies an in-process Foundation transport boundary for the actual game integration. The trusted loader installs it once before game startup, with explicit origins and exact method/path handlers admitted from verified current contracts. The public installer requires the actual HTTP ABI to be loaded; the bootstrap-private early installer described below instead runs after source-file pinning and before the reviewed image loader. There are deliberately no built-in game routes, live origins, credentials, login fixtures or invented success responses. Empty routes reject all requests. Async handlers can call the existing `ODNativeCore`, but original response projection must be implemented from real current schema evidence before admission; the core's internal JSON is not assumed to be the game's JSON.

All HTTP(S) requests reaching this installed protocol are handled locally or fail with fixed errors. An empty origin/route configuration is permitted as an all-HTTP-rejected startup policy; nonempty routes require approved origins. Unknown origins/routes, streamed bodies, URL credentials/fragments, encoded/noncanonical paths, duplicate route registrations and redirect responses reject. Queries reject by default. No source headers are copied into local requests, and no network connection is created. Requests/responses are immutable bounded byte snapshots (8MiB/32MiB); callbacks are serialized, cancellation is honored, duplicate completions reject and local errors do not leak body/URL/account values. Handlers must return promptly and complete asynchronously when needed; a bounded timeout ends an abandoned completion.

The only scalar-query opt-in is an exact native route's `scalarQueryValidator`. Its immutable `request.queryFields` contains raw ASCII strings, without percent/form decoding or array/repeated-key support. Parsing is bounded to 8,192 characters, 64 pairs, 128-character keys and 512-character values; unknown keys and unproved value forms must fail the route's policy. Existing route initializers retain rejection of every query. A validator also sees an empty dictionary when there is no query, so required flags cannot disappear silently. The actual Resources1496 producer writes literal scalar `key=value` pairs; its Json boolean reader emits `true`/`false`. This does not automatically register Resources/Home routes. `timewarp` remains raw transport metadata and never becomes a gameplay clock. See `../protocol/player-home-team/home-resources-contract.json`.

`ODRearmLocalTransportForLoadedOriginalOrigin` is bootstrap-private and main-only. After pinned engine loading, the loader-issued `ODOriginalNativeOrigin` must still validate against the actual loaded image/configuration. One transition from the installed empty-origin/empty-route deny-all state can admit owned routes while retaining the same serial queue. No generic origin setter exists. Captured old-configuration requests fail with a fixed error, and their activity/completion checks cannot deliver an old success. The diagnostic never invokes this transition. See `native-origin-source-evidence.json` and `../../research/native-origin-cold-lifecycle-contract.json`; native compilation and runtime delivery remain unverified.

Native handlers may observe `request.isActive` on any queue. It uses a weak protocol owner and synchronized activity/configuration checks. This is a snapshot, not atomic cancellation rollback; the transport independently suppresses late/duplicate/cancelled delivery. `plainJSONResponseWithObject:` encodes an owned DTO as HTTP200 `application/json`, rejecting root `sign` even when null and checking the serialized object again. Callers still own their exact DTO schema and save/lifecycle admission. `handleRequest:completion:` lets a native host wrap an immutable route without exposing a mutable handler.

Explicit optional Creator AI/download operations use `ODNativeCreatorAuthorizedRequest`, not a global protocol removal or JS/header bypass. The native tool context authorizes the exact URL once on its execution path and issues an opaque request property registered by object identity. Loading then checks current atomic revocation, exact URL/method/body digest and bound custom/auth/cookie headers; arbitrary copied tags or changed requests fail. Only HTTPS and explicitly authorized127.0.0.1 HTTP are eligible. Redirects require a new native authorization, and streaming/>32MiB bodies remain unsupported. URL policy is never called on an arbitrary loading thread; the current predicate must be thread-safe and must not synchronize onto main. Approved scoped sessions disable implicit credential/cookie storage and cancel on context close. Untagged original game/SDK traffic remains local-only. This exception does not contain transports outside the Foundation protocol, and the scoped WKWebView preview retains its own separate loopback/content/owner restrictions.

Bounded static analysis of the actual main executable now establishes the relevant Foundation loading path: `HttpAsynConnection.startRequest:` forwards its original request argument unchanged to `-[NSURLConnection initWithRequest:delegate:startImmediately:]`, using itself as delegate and `startImmediately:NO`, then schedules that connection on the current run loop and starts it. The argument must therefore be compatible with Foundation's request initializer; it is not a dictionary to reinterpret at this entry. The response delegate reads `allHeaderFields`/`statusCode`, clears its mutable response buffer, and appends received data. Finish sets the connection's completion byte; it does not directly dispatch an engine callback. Preserve that real Foundation/delegate path rather than fabricating a manual completion call.

Registration exposes this protocol to the verified `NSURLConnection` loading layer before the game creates its connections. For any separately created `NSURLSession`, `ODLocalTransportSessionConfiguration` prepends the protocol and disables URL caching, credential storage and cookie storage. This module does not intercept an already-created session, libcurl/raw sockets, or WKWebView. Actual runtime interception, callback scheduling and coexistence/order with the source patcher still require verification. Startup must isolate other live source transports; no blanket offline guarantee is inferred from registration alone.

## Original-client launcher entry

`ODRunPinnedOriginalClient` is executable native startup glue. A genuine SDK27.1+ host calls it once on the main thread before creating `UIApplication`:

1. Reject builds compiled against older SDK headers. Header/toolchain provenance and actual display acceptance still need the hosted genuine SDK27.1 build; modifying `LC_BUILD_VERSION` does not satisfy this check.
2. Open the exact original executable and source patcher through no-follow, read-only file descriptors. Check their pinned sizes/SHA-256 and unchanged file identity/timestamps. The sources are never modified, and source patches/keys are not printed.
3. Install the local Foundation protocol before invoking any reviewed original-image loader. Unadmitted HTTP requests are rejected; no default game responses exist.
4. Invoke the trusted native loader with those read-only descriptors. The loader must verify its adapted image and refuse uncontained source patcher/other initializer dependencies. This callback does not assume `dlopen` can execute an unchanged `MH_EXECUTE`, and it must not silently fall back to it.
5. Recheck source identities, then validate the loaded real HTTP ABI and presence of `AppController`. Register the original-window/Duo scene observation/embedded-Creator bridge before application startup.
6. Invoke `UIApplicationMain(argc,argv,nil,@"AppController")`, the actual entry established from the supplied executable's main implementation. The real original delegate performs its game/Cocos setup. Any failed gate returns `EXIT_FAILURE` without an online/original-main fallback.

The launcher takes explicit native loader and scene-registration callbacks; neither is a remotely supplied command or Creator/WebView operation. The scene callback must register the verified original-window attachment before `UIApplicationMain`; it must preserve the original delegate/render view rather than launch the rejected replacement game. No constructor installs this glue automatically and no speculative `startRequest:` swizzle is provided. Root's reviewed loadable-image adapter, source initializer containment and the real scene configuration remain dependencies. The source-patcher descriptor is for input identity/review; providing it does not authorize blindly executing that library.

## Same-owner Creator projection and edit lease

`ODNativeCore` now exposes native-only projection admission, synchronization and a typed `ODNativeCreatorLease`. These APIs execute on that existing owner's serial queue and private bridge; no second core connection, KVC discovery, raw core pointer or WebView-selectable trusted operation is introduced. `matchesSaveURL:masterURL:contentID:` compares the immutable owner URLs/content, while read admission returns the actual persisted save/profile/content scope for choosing private scope-keyed workspace/sidecar paths. Foreign-scope files are preserved and reject; there is no silent identity stripping, replacement or project adoption.

Synchronization calls the real C reconciliation writer: current snapshot, exact-generation definitions, source/master admission, durable sidecar commit, native persisted-state readback and only then core acknowledgement. The returned clean receipt requires matching content, save/profile scope and applied projection generation. Scope hashes compact ASCII `[save_identity,profile_id,content_id]` using the exact native content ID, including supported `eclipse:`/`sparking:` provenance prefixes. It is a dedicated projection generation; unrelated same-player XP/training does not invalidate it. Failed/stale/unsupported projection leaves the authoritative draft/core data intact and never manufactures a clean result. The C writer's actual changed-boundary pipeline evidence is in `../master/native-reconcile-evidence.json`; no original-engine row hook is inferred from sidecar synchronization.

After initial clean synchronization, the native issuer acquires the exact typed lease on the owner queue. Save import/reset through that owner and generic `creator.*` requests reject while the lease is held; same-scope normal progression remains allowed. The original-mode Session passes that exact object plus pinned scope to the narrow scoped `creator.library`, `creator.export` and `creator.finish` entry. It rechecks the actual save identity **before** C execution within the same queue block, preventing an old editor from minting into a different imported save at the same path. Release requires the same capability object and current clean scope/generation; a later editor's same-scope lease cannot be borrowed by a stale callback. The native host must route all replacement/rebinding through its owner and avoid competing core/file writers.

Acquisition/reconciliation/release replies return asynchronously to main. A presentation canceled before a late acquisition reply must release its returned clean lease rather than drop it. The Creator coordinator must preserve its editor and both native/engine pause leases on failed save/sync; dismissal/resume follows only matching clean reconciliation and correct release. Actual UIKit/runtime integration still needs the focused native cohort and physical acceptance.
