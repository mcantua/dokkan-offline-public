# Actual native master acceptance boundary

The new cold-copy adapter is preparation, not native acceptance. Independent
source review found no blocking I/O defect; native compilation/execution and
cipher compatibility remain unverified. Integrated startup remains closed.
An AppController scene or the original asynchronous worker completion cannot
open this gate.

Three new exact source bodies were reviewed in their own scopes: selected
language36bytes, first schema check340bytes and compatibility retry232bytes.
Ghidra reported no out-of-body sites; direct ARM64 call/return instructions
were also checked independently. Exact hashes are recorded in
`native-master-acceptance-frontier.json`. Coordinates and assembly remain in
the ignored private research folder. No key provider or key value was examined.

The actual language getter calls a12-byte accessor returning the address of a
native libc++ string, then returns its short/long-string data pointer. It does
not choose a host language. That global's initialized/current value, its
initialization order and native resource-prefix setting remain unobserved.
Reading a guessed default before loading the engine would not establish the
selected language. The cold-stage API therefore has no admitted caller yet.

The actual native first schema checker operates on the database manager's own
cached handle. It constructs the source query wrapper, executes the original
setup statements and returns the result of the source's
`select * from sqlite_master; ` executor. The compatibility helper executes the
source compatibility3 statement; a zero result returns0, otherwise it returns
the original first checker result. These are observations of unchanged native
code, not settings copied into our host.

The316-byte cached-open wrapper is the useful result boundary, with important
qualifications. An already-present cached handle returns1 without a fresh open.
With no cached handle, it invokes the preferred candidate and, on failure, the
nonempty fallback. It retains that open/key result. The native first/compatibility
checks then choose the normal continuation or replace the result with16. A
single result therefore cannot identify whether the downloaded master or bundle
seed was selected. The104-byte outer caller can retry after16 using another
original candidate. Merely recording a later successful callback could hide an
invalid preferred database and successful seed fallback.

The276-byte original worker calls the152-byte initializer and schedules its
captured completion. That completion does not carry the actual open/schema
result or selected-file identity. The152-byte initializer may also reuse an
existing handle. Neither that completion nor the later renderer is a verified
master-admission callback.

The smallest future diagnostic must passively observe the existing original
execution rather than call an invented wrapper ABI. In a fresh own container,
record the native language/prefix and which exact candidate resolves; at the
original cached-open boundary record cache-empty entry, preferred/fallback
attempt identities, source open result, first/compatibility schema outcome and
final result, and observe the native cache's lifetime without replacing it.
The selected-file identity must match the independent disposable working copy,
not the immutable source or bundled seed. Record only fixed codes and
nonpersonal content/inode identity, with no key bytes, request/account data,
raw private paths or database rows. A debugger/observer installed before dyld
initializers is a possible diagnostic mechanism, but none is currently
implemented/admitted; no function-pointer cast, native callback signature,
inline patch or debugger command is silently authorized by this document.

The existing source startup diagnostic remains fallback-only. A distinct,
explicit future preferred-master diagnostic option needs a proven language/root
contract before its cold stage can run and an actual observation mechanism
before it can report acceptance. It must preserve the original asynchronous
execution/cleanup ownership and never invoke the unsafe close/reopen wrapper
from the host. If native validation deletes the working copy, preserve the
immutable source and report failure rather than retrying over existing state.
A native build/run requires Tin's existing explicit build instruction; none was
performed here. No master acceptance, first home or real battle is claimed.
