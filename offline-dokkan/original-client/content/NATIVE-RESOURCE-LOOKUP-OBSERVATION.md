# Observe the original resource resolver

`ODOriginalResourceLookupProbe` asks the actual initialized engine whether four
fixed, retained original iPhone resources resolve by their canonical,
`assets/`-prefixed, or original `tutorial0/` names. It performs at most twelve
native filename lookups per explicit observation. It is not a per-frame poll
or a startup, master, Creator, or gameplay gate.

The loader issues the optional capability from its existing admitted image
snapshot. The factory resolves unique pinned source bodies and the existing
singleton storage/vtable relationship without calling the singleton getter or
constructing anything. Observation requires a live pinned original application,
Director and scene, current mapped bodies, and the original Apple string ABI.

The report contains fixed keys and booleans only. It compares returned paths
against exact own-bundle and own-Documents paths and checks those expected
files with `NOFOLLOW` directory traversal. It never follows or stats an unknown
returned path. It does not read or rehash CPK contents, decode media, access
keys/saves, accept page or HTTP filenames, or change search paths. The original
resolver may populate its normal filename cache as part of the lookup.

This source is not yet compiled, integrated or executed. Its evidence is
`native-resource-lookup-observation-source.json`. The optional provider belongs
to the next reviewed cohort; lack of a probe must preserve original startup.
