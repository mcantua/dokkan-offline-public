# Complete Creator capability inventory

## Current implementation after the baseline audit

The counts below describe the **baseline missing bridge**, not the latest implementation or runtime completion. The source now wires the actual iPhone adapters/ForgeHost/ForgePlayer into the original-client Creator. `ODBoundOriginalCreatorServices` issues one scoped tools instance alongside the exact native Session/Core lease, and the coordinator injects it before WK creation. Controller routes only the scoped tools scheme endpoints, registers `ForgeHost`, lays out its actual player and invalidates tools on main before owner release. Native network authorization defaults denied and stays host-owned.

`creator-ui/build.py` now stages the actual iPhone adapters/workers/vendor runtimes/licenses plus an explicit list of public/authored reference metadata. It does not copy private game databases, game media, APK/IPA, source keys or the standalone iPhone project's database installation. Original-mode bootstrap requires the full scoped tools rather than falling back silently. The real Save/export screen, source tools/download screen, wiki reference and artwork are retained alongside the native Finish panel; the former stub/hiding behavior remains only in the legacy restricted internal host.

The new `ios-tools-adapter.js` keeps projects/versions/settings/Finish and character queries on the same pinned `ODCreatorSession`. Both legacy source labels refer to one selected master. The bounded native `creatorMasterRead` is single-statement readonly with a SQLite authorizer, parameters, table/function restrictions and row/column/length/byte/VM/time limits; it cannot choose a database/path or query the player Core. The actual iPhone asset/animation/media/AI/Files/export implementations remain responsible for their existing tools. Source format admission/keys are native-only, and switching the player's master while the editor lease is active is explicitly refused rather than writing an alternate database behind the owner.

Native-only archive adapters export/restore only virtual project/version files on Session's serial queue; raw state, intents, definition IDs, preferences, master and player data never leave. Restore checks revisions and conflicts and commits all document changes atomically. Creator reset now clears the authoritative editor documents rather than falsely deleting only legacy tools files; it leaves the actual game collection/progression alone.

One combined affected native syntax check passed with the actual pinned16.5 headers and Werror; changed frontend syntax passed. This is **not** SDK27/Duo runtime parity evidence. Native source codec/archive registration is being integrated with their owners. Actual original-engine consumption of custom art/forms/animation abilities remains separate unfinished work, and genuine hosted Finish is still unresolved pending its precise saved-growth diagnosis. No full tool runtime or gameplay completion is claimed.

Loading its controllers is not evidence that all features work: the existing settings bridge cannot presently supply the full native services the screens request. Do not advertise it as complete or remove the unsupported screens to conceal that gap.

## Concrete reuse boundary

The production iPhone build stages `web-native.js` followed by `ios-host.js`, `ios-native.js`, `ios-formats.js`, `ios-preview.js`, `ios-player.js`, `ios-assets.js`, `ios-sparking.js`, `ios-offline.js` and `ios-io.js`. Their `H` handlers operate through `ForgeHost`, its `app://` file/net/mirror scheme and `ForgePlayer`. The current Offline stage instead loads only the shared UI plus its restricted `host-adapter.js`; it does **not** load those complete iPhone adapters or register `ForgeHost`/the editor player. Whitelisting more names alone cannot restore these features.

Reuse those actual implementations through a native-scoped tools host. Its private file/download namespace must remain separate from immutable selected master/core/save/owner-marker files while referring to the same unit/project/asset context. Keep selected-master queries and project/Finish/version authority on the existing pinned `ODCreatorSession`; do not let generic iPhone SQL or `installDatabases` replace the master/core. `ForgeHost` currently uses static `StorageRootPath`/`ResolvePath` and global public download aliases, so a subclass override of `+storageRoot` alone does not scope its internal reads/writes. This must be refactored or wrapped deliberately before reuse.

Retain native Keychain secrecy and actual Files picker/Share behavior. Existing `secretGet` JS convenience is not implemented as a raw native key read; `Host.m` only supplies hint/set/delete and native-authenticated AI requests. Do not broaden it to return secrets. Network/download services are user-invoked tools, not a dependency for ordinary offline gameplay. Editor media/animation preview must remain distinct from original-game execution.

The new original-client session blocks only the rejected `offline-dokkan/gameplay/` harness and its native game operations. It does not make the missing Creator tool capabilities optional, and it must not disable the existing editor preview engine while restoring them. Actual game return remains the native controller/coordinator path. No app package, browser rebuild or broad test suite was run for this source inventory.
