# Genuine cloud native check

**Current gate (October 29):** this workflow is manual-only. Root coordinates a necessary Duo check after a coherent change batch; individual agent updates do not automatically run it. Android is disabled until Tin accepts the entire unified Duo app and explicitly approves starting Android. The device-package step is also disabled because it recreates the obsolete Offline save-manager IPA. Retained packaging/Android descriptions below describe historical tooling, not current authorization or production game completion. No package is generated by the enabled workflow.

The workflow first builds the complete single-file browser page from pinned source and real table snapshots, then runs one focused packed-page check. Its artifact includes the HTML, exact source/hash report, measured verification and one current screenshot. A separate scoped job commits only those four files to this chat's branch; an advanced branch is preserved. Git transport carries the embedded media runtime without removing features to fit a connector request. Native jobs use the same pinned code and generated HTML. This changes no App Installer files and publishes no release.

`Offline Dokkan unified Duo native check` is an independent, manually dispatched GitHub Actions workflow. It touches no App Installer source or workflow, Apple account, signing key, personal Mac, or physical phone. It requires the hosted `xcode-27` runner with actual Xcode27.1, simulator SDK27.1 and the iOS27.1 iPhone Duo runtime/type; it fails clearly if any is missing. It never substitutes the existing Linux16.5 SDK with an edited27.1 SDK mark, an ordinary simulator, Chromium, forced view sizes, or fixture data.

The runner reconstructs all233 actual Eclipse and233 Sparking table snapshots already embedded in `test-page/UnitCreator-test.html` into ignored cloud-only SQLite. It checks compressed-chunk hashes, delta indices, schema, all row counts and SQLite integrity before using them. A focused local reconstruction matched every original supplied DB table's row count:17,786 Eclipse cards and19,308 Sparking cards. These are reconstructed tables, not original database bytes: the browser snapshot omits indexes/triggers/views/foreign-key declarations and decodes binary columns as UTF-8. They are appropriate for actual native SQL/UI checks and cannot prove original encryption, game import/export, arbitrary binary fields, or release database fidelity. Provenance records the committed HTML hash, available original snapshot identity, reconstructed hashes and counts.

It then builds the actual `ios-objc/main.m`, `Host.m`, and `Player.m`, the full Android-derived screens and production iPhone adapters. One hosted XCTest launches that real app on one new owned Duo simulator. It checks startup ready, actual native window/page width agreement, absence of horizontal overflow, actual native SQL counts for both snapshots, and one native safe-file write/read/delete round trip. It records an actual native-window screenshot and sanitized JSON. It inspects the supported simctl help and display enumeration without claiming a fold operation: physical outer/inner folding, reserved regions, touch, keyboard, signing/device installation and game integration remain unverified.

Only that newly created simulator UUID is shut down/deleted. SDK/runtime caches and simulator storage are OS-managed on the ephemeral hosted runner. Generated project, reconstruction, app, DerivedData and raw XCResult remain ignored under `unit-creator/cloud-ui/work/`; tools stay in ignored `downloads/unit-creator-cloud-tools/`. The native check uploads sanitized JSON/text/log/screenshot evidence. The separate device packaging step described below uploads a database-free Unit Creator bootstrap and a data-free Offline development IPA; it never uploads raw DBs or simulator fixture apps. The dependent Android job builds private development test APKs.

The Duo XCTest now also requires the actual visible Home Create button and uses the current WK compositor snapshot after fonts/animation-frame callbacks. A UIKit-only hierarchy capture can contain stale launch tiles even after the DOM is ready; the original first run demonstrated that evidence flaw. The test saves the actual WK snapshot separately and places it at its real native bounds in the native-window image. It does not change product startup state. A production ECLP round trip at `app://` uses the actual Argon2 workers, AES-GCM and zstd code, records worker completion without exposing keys, and compares returned bytes. VP9 API capabilities are recorded without claiming full media playback.

That same Duo check opens the generated standalone HTML in a second real WKWebView using `loadFileURL`, a nonpersistent store and read access to that exact file only. An active WebKit content rule blocks all HTTP(S); no native bridge is injected. It waits for successful navigation and the actual Home screen, checks both embedded catalogs and page width, then calls the production lazy movie compatibility probe once. The probe must initialize the real classic worker and bundled FFmpeg WASM and report actual VP9/HCA support. `standalone-file-check.json` and `standalone-file.png` record this separate engine check. The HTML exists only in the XCTest bundle, so device applications do not acquire a duplicate browser file or its databases. This checks WebKit's file-loaded engine; Safari/Quicklook controls, physical phone behavior and a complete movie conversion remain outside its scope.

An additional hosted Offline native target uses the real C/Objective-C local-save host and bundled public SQLite3.50.4. Its DB resources are explicit **private cloud fixtures** (`OD_CLOUD_FIXTURES=1`), never redistributable Offline game content. Its one XCTest checks actual player creation/reopen, separate Eclipse/Sparking saves, the real user-master import/reselection machinery, unsupported original-game wire rejection, the rooted Darwin filesystem resolver and an actual native-screen image. Production host source has no bundled-game-data path without that fixture flag.

The Ubuntu Android job runs only **after Duo passes**. It creates one disposable API35 x86_64 AVD with pinned official emulator37.3.6/image-r09, real KVM and software GPU; no local emulator is attempted when this cloud workspace lacks `/dev/kvm`. It builds the actual retained original dex plus current native Java/UI against pinned SDK35, includes the reconstructed private CI snapshots, installs the coexisting development APK, and reaches its actual WebView through adb/CDP. DOM interactions open Home/Create, select a real native-SQL character, create/save a unit and verify the same unit after a real force-stop/relaunch. It records actual Android framebuffer screenshots and unhandled JavaScript exceptions. It never injects browser-native adapters or fake backend responses. Managed storage permission is granted only for this disposable development package; physical touch and its permission dialog remain unverified.

Android source/build/AVD/evidence stay under ignored checkout directories; only OS-managed hosted toolcache/virtualization services are outside them. The current private Android artifact includes its installable development test APK and evidence, never raw DBs, signing files, adb keys or player data directories. That CI APK's reconstructed data differs from the personal local development APK containing Tin's supplied original databases; provenance distinguishes them. The workflow removes prior matching evidence only after a **successful native check and upload**, so a failed diagnostic upload cannot destroy the last working proof. It never prunes App Installer or other workflow artifacts.

After the native Duo checks pass, `package-device.sh` compiles Unit Creator once using **actual iPhoneOS27.1**, arm64 device target, original `com.dokkanunitcreator.ios` bundle and `App` executable. It never edits an SDK mark or passes a simulator binary off as a device binary. The private artifact contains a small checked `UnitCreator-genuine-device-bootstrap.zip` with all tested native/site/icon files and exact component/source hashes, deliberately omitting the reconstructed fixture databases. Root runs `python3 unit-creator/tools/repack-cloud-ipa.py BOOTSTRAP.zip genuine-device-bootstrap.json` locally in this cloud workspace to verify matching current native/site source, restore the supplied **original database bytes**, verify their counts/integrity/hashes and ZIP/Duo gates, and atomically replace only the current IPA. Apple identity signing/provisioning and device launch remain separate pending checks.

The same device step builds the separate Offline save-manager0.1.0/code1 with `OD_CLOUD_FIXTURES=0`, and excludes every private fixture DB/provenance resource from its final unsigned IPA. That distributable own-app candidate contains no game database/assets. Its import screen uses the user's own Files selection. A physical Apple signature/installation is not claimed.

The already-owned Android emulator also installs that project's separate **data-free** APK, imports a private runtime master fixture through the actual system Files picker, and checks the actual JNI/C/SQLite player reopens after force-stop. The source selected in Downloads must keep the same SHA256. No fixture is inserted into the Offline APK and no original game endpoint or reward is invented. The UIKit/native Files picker/Android accessibility checks use real platform components; only the browser snapshot table data is a clearly identified reconstructed test input.

PR updates no longer trigger this workflow. It supports manual dispatch after the workflow is available on the default branch; no hosted result is claimed merely because its YAML exists locally. Existing source-matched passing evidence is reused; a specific changed risk or unresolved failure is needed before requesting another native run.

Tool provenance: Xcode and simulators are the installed hosted Apple toolchain recorded in `toolchain.json`. XcodeGen2.46.0 is downloaded from `https://github.com/yonaskolb/XcodeGen/releases/download/2.46.0/xcodegen.zip`, SHA256 `4d9e34b62172d645eed6457cac13fc222569974098ef4ee9c3368bedf0196806`, MIT licence. Its ZIP/binaries are not committed.
